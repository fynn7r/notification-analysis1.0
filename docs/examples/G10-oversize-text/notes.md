# G10：超长文本

**测什么**：一段 5.2 万字的通知（模拟把整本手册粘进来），超过 5 万字上限。

**期望**：400 `INVALID_REQUEST`，提示「通知暂限 50000 字以内」，**不发出模型请求**。

**为什么值得测**：超长文本有三种糟糕的处理方式——静默截断（用户以为全解析了）、发出请求然后被上游截断（耗时又费钱）、抛一个看不懂的错误。这里要求的是第四种：**在花钱之前就拒绝，并说清字数上限。**

**为什么上限是 5 万而不是更大**：不是模型撑不住（2 万字中文只占上下文的零头），是准确率。文中越长，模型越容易把「报名截止」和「活动开始」搞混——那正是 G6 要防的错。这条护栏宁可让超出的部分被明确拒绝，也不让模型在长文里自信地挑错日期。

**通过判据**：错误码为 400，且提示里带出具体的字数限制。

**与 G13 的关系**：G10 守「超了要拒」，G13 守「没超要放行」。两条缺一条，上限就可能被悄悄改坏——只测拒绝会让人以为上限越小越安全，只测放行则看不出护栏在哪。
