便携版已重新打包，含本次全部改动，下载解压双击 `start.bat` 即可用。这一版把「闭环」补上了：待办不再只存在本机，登录后进 SQLite，可以跨设备；导出也从只有日历补到日历 + 表格两条路。

## 这个版本改了什么

**1. 待办进 SQLite，换设备也能看到**

以前所有数据都躺在浏览器 localStorage 里，换个浏览器、清一次缓存就没了。现在登录后待办存在服务端，换设备重新登录即可看到。未登录仍然纯本地，不受影响。

设计上做了三个取舍：

- **内存是权威副本，读永远同步**。定时器检查待办到点时不能等网络，所以读操作一律命中内存，服务端的更新是异步回填。
- **写不阻塞**。先改内存立刻渲染，再排队推给服务端，失败进重试队列。不会因为网络慢就让点一下卡三秒。
- **登录不等于覆盖**。首次登录时如果云端是空的本机却有东西，会提示「发现 N 条本地待办」让你决定是否导入，而不是直接把本地清空。

**2. 「已保存」不再误报**

这是上一版真实存在的 bug。旧代码判定「存上了没有」的方式是回读 localStorage，但登录后数据落在 SQLite，回读必然为空——于是刚存好的待办被判成失败，还会被删掉。改成只看内存又走到另一个极端：浏览器存储配额满的时候，内存里有、磁盘上没有，刷新就没了，界面却告诉你「已保存」。

现在要求「内存里记得」和「最近一次落盘成功」两个条件同时成立才提示成功，否则保留核对面板让你重试。

**3. 删除不再复活**

原先按物理删除处理。A 设备删掉一条，B 设备刷新时用旧快照回推，这条又活过来了。改为软删墓碑（`deleted_at`），同步时把删除意图也下发给另一端。

**4. 导出补齐两条路**

- **导出日历（`.ics`）**：符合 RFC 5545，带 `VALARM` 闹钟。时间用 UTC 实例而不是 `DTSTART;TZID=`，因为后者要求文件里带匹配的 `VTIMEZONE` 组件，缺了它 Outlook 和部分安卓日历会把墙钟时间当成 UTC 读，整体偏 8 小时。没有截止时间的待办会被跳过，并明确告诉你跳过了几条。
- **导出表格（`.csv`）**：给「想自己再算一遍」的人——统计这学期有多少件事、导给班委汇总、贴进 Excel 做台账。带 BOM（否则 Excel 在中文 Windows 上按 GBK 解码，中文全变乱码）与 CRLF。与 `.ics` 不同，它不做时间过滤，没有截止时间的待办也留在表格里。

**5. 默认提前量可配置**

核对弹窗里新增「提醒提前量」下拉，改动会同时写进个人偏好，下次打开沿用。如果你直接手改提醒时间，会按两个时间的差值反推提前量，而不是相信下拉框里那个旧值。

**6. 脏数据不再白屏**

写导出测试时用错了重要度的取值（写成「高」而不是 `high`），整个页面直接白屏。数据是从 localStorage / SQLite 读回来的，历史版本或手工改过的记录里出现这种没归一化的值完全合理。现在未知值退到「中重要」，一个徽章不该带走整个页面。

## 还有一处没有变成新前缀

取代平台 SDK 存储封装时，本来可以顺手把键名从 `__app_notizhi_*` 换成更干净的 `__notizhi__:*`。没有换，因为换前缀等于换 key：所有已经在用户浏览器里的数据会变成孤儿，而 `__app_notizhi_*` 已经是既成契约——回归测试、开发者工具里的手工改写、用户自己写的脚本认的都是它。统一但不改写。

## 已知限制

- **提醒依赖页面处于打开状态**。网页应用在完全关闭时无法响铃，这是浏览器能力边界。导出 `.ics` 到系统日历可以绕开。
- **扫描版 PDF 读不出文字**，需要文字层。
- **合计 20000 字上限**，原文优先占用。
